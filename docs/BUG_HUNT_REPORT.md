## 1. Executive Summary

**Finding counts**

**Top risks**

1. **Critical**: `rustre-flirt` and `rustre-flirt-apply` use two different CRC16 algorithms (CCITT-FALSE vs ARC). Every signature verification with `require_crc=true` silently rejects all valid matches. This makes the whole FLIRT pipeline functionally broken against real IDA-format signatures.
2. **Concurrency / unsoundness**: `rustre-mem::EmulatedMemoryProvider` (and `TraceMemoryProvider`) declare `unsafe impl Sync` while performing unsynchronized `&mut *UnsafeCell` writes inside `&self` methods — a data race reachable from 100% safe code via `Arc<dyn MemoryProvider>`.
3. **UB in test code**: `rustre-gui` panels (`symbols_panel.rs:1456`, `disasm_panel.rs:2036`) build `FocusHandle` via `mem::zeroed()`. Drop of the zeroed `Arc` is UB and may produce nondeterministic `cargo test` crashes.
4. **Workspace cohesion**: At least 30 substantive sub-crates (debug backends, mobile-*, fuzz-*, loader-*, arch-*, analysis-*, deobf-*, threat-intel providers, script backends, symbol-format backends, trace backends, IL stack, hex extensions, ttd-*, sandbox-*) are compiled but never linked into any facade or binary. They are dead code from the user's perspective.
5. **Logic bugs in core analyses**: BPF unsigned compares collapse to `==/!=`; BPF/AVR/m68k/RISC-V arithmetic shifts are lifted as logical shifts; ETM3/ETM4 atom decoding is incorrect; bindiff prime table assigns duplicate primes to distinct mnemonics; LLIL interpreter panics on `i64::MIN / -1` and on rotate-by-0 of Qword.

**Top recommendations**

1. Fix the FLIRT CRC mismatch immediately — replace `signature_matcher::crc16` with the CRC-16/ARC routine already used elsewhere in the workspace.
2. Either drop `unsafe impl Sync` on `EmulatedMemoryProvider`/`TraceMemoryProvider`, or wrap their `PageCache` in `Mutex`/`RwLock` (the pattern `ProcessMemoryProvider` already uses).
3. Replace `mem::zeroed()` test constructors with a real `TestAppContext` or convert `focus_handle` to `Option<FocusHandle>`.
4. Wire every "facade" crate (`rustre-debug`, `rustre-loader`, `rustre-arch`, `rustre-analysis`, `rustre-deobf`, `rustre-trace`, `rustre-ttd`, `rustre-threatintel`, `rustre-emu`, `rustre-fuzz`, `rustre-script`, `rustre-symbols`, `rustre-sandbox`, `rustre-mcp`, `rustre-flirt`, `rustre-diff`, `rustre-triage`, `rustre-net`, `rustre-forensics`, `rustre-hex`) to its sibling backends as feature-gated dependencies, and re-export their public types.
5. Delete clear duplicates: `rustre-ttd-replayer` (superseded by `rustre-ttd-replay`), one of `mips_lift`/`mips_lifter`, one of `riscv_lift`/`riscv_lifter`, `pe_rebuild.rs` module inside `rustre-pe-tools`.
6. Run a sweep replacing panicking arithmetic (`offset + N`, `lv / rv`, `1u64 << (bits-1)`, `partial_cmp().unwrap()`) with checked / `total_cmp` / `saturating_*` variants across `rustre-core::endian`, `rustre-il-llil`, `rustre-analysis-vsa`, `rustre-agent-llm`, `rustre-debug::expression_evaluator`.

## 2. Critical Bugs

### C-1. FLIRT CRC algorithm mismatch between matcher and applier

- **Crates**: `rustre-flirt`, `rustre-flirt-apply`
- **Files**:
  - `crates/rustre-flirt/src/signature_matcher.rs:200` — CRC-CCITT-FALSE (init=0xFFFF, poly=0x1021, no reflection)
  - `crates/rustre-flirt-apply/src/apply_engine.rs:75` — CRC-16/ARC (init=0, poly=0xA001, reflected)
  - `crates/rustre-flirt/src/lib.rs:220` (`crc16_flirt`) — CRC-16/ARC
- **Impact**: IDA FLIRT uses CRC-16/ARC. Patterns generated by `rustre-flirt-gen` (ARC) are verified by `signature_matcher` (CCITT-FALSE). When `require_crc=true` (the default per `signature_matcher.rs:242`), every valid signature match is silently rejected. End-to-end FLIRT-based function recognition is non-functional.
- **Fix**: Replace `PatternMatcher::crc16` in `signature_matcher.rs` with the same CRC-16/ARC implementation used in `apply_engine.rs` / `lib.rs::crc16_flirt`. Update the test vector to `0xBB3D` for `"123456789"`. Add a workspace-level test asserting both implementations agree.

## 3. High-Severity Bugs (grouped by category)

### 3.1 Unsoundness / UB

- **mem::zeroed() on FocusHandle in symbols panel test** — `crates/rustre-gui/src/ui/panels/symbols_panel.rs:1456`. Zeroed Arc → UB on drop. Fix: use `TestAppContext::new_focus_handle` or change field to `Option<FocusHandle>`.
- **mem::zeroed() on FocusHandle in disasm panel test** — `crates/rustre-gui/src/ui/panels/disasm_panel.rs:2036`. Same pattern, same fix.

### 3.2 Concurrency

- **`unsafe impl Sync` over unsynchronized `UnsafeCell` in `EmulatedMemoryProvider`** — `crates/rustre-mem/src/provider.rs:197` & `read()` at `:221`. Data race on `PageCache` reachable from safe code.
- **Same pattern in `TraceMemoryProvider`** — `crates/rustre-mem/src/provider.rs:682` Sync impl, `:787` unsynchronized `&mut` from `UnsafeCell` in `read(&self)`.
- **`FunctionRegistry::register` splits write lock** — `crates/rustre-script/src/script_context_full.rs:216-249`. Between the two write locks (signatures, impls), a concurrent `call` can observe inconsistent state and return spurious `FunctionNotFound`; `remove` symmetric.

Fix template: replace `UnsafeCell<PageCache>` with `Mutex<PageCache>`; merge the two `RwLock` maps in `FunctionRegistry` into one `RwLock<HashMap<String, (Sig, Impl)>>`.

### 3.3 Arithmetic / Panics

- **`StridedInterval::cardinality` overflows on near-top intervals** — `crates/rustre-analysis-vsa/src/strided_intervals.rs:123`. Fix: widen to `i128`.
- **`EndianRead::read_u{16,32,64,128}` panic on offset near `usize::MAX`** — `crates/rustre-core/src/endian.rs:169,181,193,205`. Reachable from every binary loader. Fix: `offset.checked_add(N)?`.
- **`pretty_print` signed B16 shift overflow** — `crates/rustre-debug/src/expression_evaluator.rs:1504`. `1u64 << 127` panics. Fix: special-case B16.
- **LLIL `DivS`/`ModS` panic on `i64::MIN / -1`** — `crates/rustre-il-llil/src/llil_interpreter.rs:772,789`. Fix: `checked_div`/`checked_rem`.
- **LLIL `Rol`/`Ror` panic on shift==0 (Qword)** — `crates/rustre-il-llil/src/llil_interpreter.rs:830,837`. `u64 >> 64` is UB-shift. Fix: use `u64::rotate_left/rotate_right`.
- **`partial_cmp().unwrap()` on f64 model scores** — `crates/rustre-agent-llm/src/model_registry.rs:264,494`. NaN panic. Fix: `total_cmp` or `unwrap_or(Ordering::Equal)`.
- **`InputQueue::select`/`select_cursor` panic on empty queue (public API)** — `crates/rustre-fuzz/src/lib.rs:497-535`, also `afl_corpus_manager.rs:637,648`. Fix: return `Option`.

### 3.4 Logic

- **`StridedInterval::meet` uses `lo` instead of `adjusted_lo`** — `crates/rustre-analysis-vsa/src/strided_intervals.rs:172`. Drops valid intersection elements. Fix: `adjusted_lo + ((hi - adjusted_lo) / s) * s`.
- **`TaskGraph::add_task` allows silent ID collisions** — `crates/rustre-agent/src/task_planner.rs:205`. `HashMap::insert` overwrites without checking collisions; `next_id` not bumped on manual id < next. Fix: reject collisions or `next_id = max(next_id, id) + 1`.
- **Unary `AddrOf` returns value instead of lvalue address** — `crates/rustre-debug/src/expression_evaluator.rs:1326`. Wrong for `&$reg` and `&*ptr`. (Note: file is currently orphaned — not registered in `lib.rs` — so impact is latent.) Fix: separate `eval_lvalue` path.
- **bindiff prime table assigns prime 211 to `jne`, `jz`, `jnz` (and 199 to `je`)** — `crates/rustre-diff-bindiff/src/prime_product_hash.rs:85-88`. Collisions destroy hash uniqueness; `je`/`jz` (aliases) disagree while opposite-polarity branches collide. Fix: unique primes + debug-assert at table construction.
- **`FunctionMatcher::compute` byte-slices UTF-8 names** — `crates/rustre-diff/src/function_matching.rs:119`. Panics mid-codepoint. Fix: `name.get(..8)` or char-based take.
- **`InstructionNormalizer` alpha-rename is incoherent** — `crates/rustre-diff-bindiff/src/instruction_diff.rs:132-157`. `next_reg_id` increment uses a nonsense post-check; distinct regs map to the same `r0`. Fix: entry API with vacant/occupied branching.
- **`apply_matches` reports both rename and conflict for same address** — `crates/rustre-flirt/src/signature_matcher.rs:391-422`. Conflict is appended without rolling back the earlier rename. Fix: buffer per address, then decide.
- **`crc_check_passed` reported true even when not computed** — `crates/rustre-flirt/src/signature_matcher.rs:287-336`. `crc_ok=true` when `require_crc=false` or `pat.crc16==0`, also `+0.10` confidence inflation. Same for `tail_check_passed`. Fix: distinguish verified vs skipped.
- **`AppliedSymbols.high_confidence_count` double-counts on overwrite** — `crates/rustre-flirt-apply/src/recognition_session.rs:210-215`. Counter exceeds map length. Fix: decrement prior contribution on overwrite, or recompute at end.
- **`Ord` inconsistent with `Eq` for `MatchCandidate`** — `crates/rustre-flirt-apply/src/recognition_session.rs:45-66`. Violates `BinaryHeap`/`BTreeMap` contract. Fix: align tie-breakers.
- **`EditBuffer::write` / `HexBuffer::write` silent truncation past EOF** — `crates/rustre-hex/src/hex_editor_core.rs:284`, `crates/rustre-hex/src/lib.rs:693`. Caller is never informed of partial write; undo entry stores truncated bytes. Fix: return `OutOfBounds` when `offset + len > buffer_len`.
- **Regex search `len=1` for every match** — `crates/rustre-hex/src/lib.rs:1184`. `replace_all` then corrupts buffer for multi-byte matches. Fix: thread real `end` from `ByteRegex::find`.
- **BPF unsigned compares collapse to `==/!=`** — `crates/rustre-il-lift/src/bpf_lifter.rs:218-252`. All `jgt/jge/jlt/jle` lose magnitude. Fix: add `CmpUltU/CmpUgtU` IR nodes or `Effect::Intrinsic`.
- **BPF/AVR/m68k/RISC-V arithmetic shifts lifted as logical shifts** — `bpf_lifter.rs:533`, `avr_lifter.rs:560`, `m68k_lifter.rs:422-430`, `riscv_lifter.rs:430,434`. Sign bit lost. Fix: introduce `IrExpr::Sar` or intrinsic wrapper.
- **Phi-node `vals[0].unwrap()` panics on empty sources** — `crates/rustre-il-mlil/src/mlil_ssa.rs:486`. `iter().all` is vacuously true on empty. Fix: guard `if sources.is_empty()`.
- **Dex branch-target heuristic mis-classifies negative offsets as absolute addresses** — `crates/rustre-il-lift/src/dex_lifter.rs:1257`. Sign-extension of `-1` to `0xFFFF…` bypasses `<= 0xffff` check. Fix: parse as `i64` and check signed range.
- **`PacketCraft::build` writes stale IPv4 `total_length` & checksum** — `crates/rustre-net/src/packet_builder.rs:613-627,666`. `PacketBuilder::ipv4` hardcodes `payload_len=0`, never updated. Fix: recompute at `build()` time.
- **`PacketCraft::build` never computes TCP checksum** — `crates/rustre-net/src/packet_builder.rs:603-611`. Always 0; receivers drop. Fix: invoke `checksum_ipv4` post-serialization, patch bytes 16..18.
- **Lua `LocalAssign` writes to globals** — `crates/rustre-script-lua/src/lib.rs:656-659`. No scope stack. Fix: introduce `Vec<HashMap<String,LuaValue>>` scope frames.
- **C13 line entry parser interleaves columns with line entries** — `crates/rustre-symbols-pdb/src/line_info.rs:205-221`. Per CodeView spec, columns are a parallel array after the line array. Fix: two-phase read.
- **`S_LPROC32` aliased with `S_REGREL32` (`0x1111`)** — `crates/rustre-symbols-codeview/src/cv_function_info.rs:35-41`. True S_LPROC32 is `0x110F`; current matcher silently mis-decodes regrel-locals as procs and drops real local procs.
- **Old _ST CodeView constants in PDB parsers** — `crates/rustre-symbols-pdb/src/module_symbols.rs:34-35`, `global_symbols.rs:15-18`, `lib.rs:338-344`. Modern PDBs never match. Fix: `S_LPROC32=0x110F, S_LDATA32=0x110C, S_LABEL32=0x1109`.
- **`to_ioc_list` drops Bitcoin / Ethereum / User-Agent IoCs** — `crates/rustre-threatintel/src/ioc_extractor.rs:80-106`. Fix: add `push_type!` lines and (likely) new `IoCType` variants.
- **`MbzVendorResult::is_malicious` true even when `detected=false`** — `crates/rustre-threatintel/src/malwarebazaar.rs:133-136`. Inflates confidence. Fix: require `detected==Some(true) && !result.is_empty()`.
- **`DrcovExport::export` writes an invalid drcov file** — `crates/rustre-trace/src/trace_export.rs:132`. Stray `Columns:` prefix + literal `--- binary data would follow ---` sentinel; consumers see zero BBs. Fix: emit canonical header + real BB rows.
- **ETM3 Atom packet: 6 atoms hardcoded** — `crates/rustre-trace-coresight/src/etm_packets.rs:317`. Branch reconstruction wrong. Fix: decode per F1..F4 sub-encoding.
- **ETM `decode_atom_f` broadcasts a single bit** — `crates/rustre-trace-coresight/src/etm_packets.rs:536`. All atoms after `i==0` reported as `N`. Fix: use full pattern field.
